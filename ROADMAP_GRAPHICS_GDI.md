# Roadmap: графический режим GDI

## Цель

При `GRAF` программа Ellochka работает в существующем GDI-окне как на отдельном экранном режиме DOS: графика, текст и клавиатурное управление находятся в графическом окне.

При `TEXT` выполнение не меняется: GDI-окно скрывается, а текстовые команды снова используют текущую консоль (`cmd.exe`, PowerShell или Windows Terminal).

На этом этапе не делаем графику внутри терминала и не отказываемся от отдельного GDI-окна.

## Принципы

- Интерпретатор остаётся одним процессом; меняются только backend-ы вывода и ввода.
- Framebuffer имеет размер 640×480 и остаётся основой для `PIXL`, `RDOT`, `LINE`, `RAMA`, `MOVE`, `KRUG`, `PAIN` и `SBMP`.
- В графическом режиме текстовая сетка имеет размер 80×30: одна ячейка занимает 8×16 пикселей.
- Переход между режимами определяется явным флагом `graphics_mode`, а не фактом существования GDI-окна.
- Старые не-графические программы и тесты должны сохранить прежнее консольное поведение.

## Этап 0. Палитра и framebuffer

### Статус

Выполняется.

### Задачи

- `GRAF` создаёт окно и 24-bit DIB 640×480.
- `CVET` меняет палитру и внешний вид уже нарисованных областей соответствующего палитрового цвета.
- `PIXL`, `RDOT`, `LINE`, `RAMA`, `MOVE`, `KRUG`, `PAIN` и `SBMP` сохраняют текущую семантику.
- Проверить, что `sample_author.ell` циклически меняет цвет фона, а GDI-окно не остаётся чёрным.

### Критерий готовности

`sample_author.ell` показывает рамку и меняющийся цветной фон в GDI-окне.

## Этап 1. Явное состояние графического режима

### Задачи

Добавить в `InterpreterState`:

```zig
graphics_mode: bool = false,
```

Изменить семантику:

```text
GRAF  -> graphics_mode = true, показать или создать GDI-окно
TEXT  -> graphics_mode = false, скрыть GDI-окно
```

Не использовать `graphics.isInitialized()` как признак режима: окно может существовать после `TEXT`, но вывод должен уже идти в консоль.

### Критерий готовности

Последовательность `GRAF -> TEXT -> GRAF` корректно переключает UI и не зависает.

## Этап 2. Текстовый слой GDI

### Задачи

Добавить в `graphics.zig` функции текстового вывода поверх DIB:

- создание фиксированного шрифта с целевой ячейкой 8×16;
- преобразование UTF-8 в UTF-16;
- рисование через `ExtTextOutW`;
- использование `ETO_OPAQUE | ETO_CLIPPED` и прямоугольника точной ячейки;
- хранение текстовой позиции в строках и колонках.

В графическом режиме перенаправить операторы:

| Оператор | Поведение в `graphics_mode` |
|---|---|
| `CLSC` | Очистить DIB цветом фона и сбросить текстовую позицию в `(1, 1)` |
| `CSIM` | Выбрать цвет текста и текущий палитровый цвет рисования |
| `CFON` | Выбрать цвет фона текста |
| `STRO` | Установить строку `1..30` |
| `STLB` | Установить колонку `1..80` |
| `LIST` | Рисовать строку в GDI-окне |

В текстовом режиме операторы сохраняют текущую ANSI-семантику.

### Критерий готовности

Начальная заставка `sample_author.ell` выводит заголовок по центру графического окна. Консоль не получает `LIST`-вывод программы во время `GRAF`.

## Этап 3. GDI-клавиатура

### Задачи

Добавить обработку сообщений окна:

```text
WM_KEYDOWN
WM_CHAR
WM_CLOSE
```

Реализовать статическую кольцевую очередь в `graphics.zig`:

```zig
const KEY_QUEUE_CAPACITY = 64;

var key_queue: [KEY_QUEUE_CAPACITY]u16 = undefined;
var key_head: usize = 0;
var key_tail: usize = 0;
var key_count: usize = 0;
```

Добавить функции:

```zig
pushKey(code: u16)
pollKey() ?u16
clearKeys()
```

Правила сообщений:

- `WM_KEYDOWN` добавляет только управляющие клавиши: Esc, Enter, Backspace, стрелки, PgUp, PgDn.
- `WM_CHAR` добавляет печатные Unicode-символы.
- Обычные символы не должны попадать в очередь дважды.

В графическом режиме:

- `KEYS` читает очередь без ожидания;
- `WAIT` ожидает элемент очереди;
- закрытие окна корректно завершает ожидание.

В текстовом режиме сохраняется `GetConsoleInputA`.

### Критерий готовности

`KEYS` и `WAIT` работают, когда фокус находится у GDI-окна.

## Этап 4. Графический MENU

### Задачи

Перенести `MENU` в GDI-текстовый слой:

- рисование пунктов через графический текст;
- выделение выбранной строки инверсией foreground/background;
- поддержка Up, Down, PgUp, PgDn, Enter, Esc;
- использование уже реализованного `DATA`.

### Критерий готовности

Главное меню `sample_author.ell` открывается, отображается и управляется в GDI-окне.

## Этап 5. Графический VVOD

### Задачи

Реализовать ввод строки в GDI-окне:

- вывод приглашения;
- UTF-8/UTF-16 буфер редактирования;
- символы из `WM_CHAR`;
- Enter завершает ввод;
- Backspace удаляет последний символ;
- локальная позиция ввода не меняет глобальное состояние `STLB`;
- при удалении очищается точный прямоугольник 8×16 цветом `CFON`;
- курсор мигает без `SetTimer`: цикл ввода вызывает `pumpMessages()`, проверяет время, инвертирует ячейку раз в 500 мс и делает короткий `Sleep(10)`.

### Критерий готовности

Файловый и математический разделы `sample_author.ell` выполняют `VVOD` без возврата в терминал.

## Этап 6. Интеграция и регрессия

### Сценарии

```text
TEXT -> GRAF -> TEXT
GRAF -> MENU -> GRAF
GRAF -> WAIT -> TEXT
GRAF -> VVOD -> TEXT
GRAF -> SBMP
GRAF -> закрытие окна
```

### Задачи

- Прогнать `sample_author.ell` по доступным интерактивным веткам.
- Проверить отсутствие регрессий в не-графических `.ell`-тестах.
- Проверить `SBMP` после рисования и текста.
- Убедиться, что консольный и графический режимы не смешивают ввод/вывод.

### Критерий готовности

Основные сценарии `sample_author.ell` работают в GDI-окне, а старые тесты сохраняют прежний вывод.

## Отложено

- Рендеринг графики внутри Windows Terminal, PowerShell или `cmd.exe`.
- ANSI/Unicode console-backend для framebuffer.
- Масштабирование GDI-окна.
- Мышь.
- Полная DOS IDE/редактор.
- Реализация framebuffer на индексах палитры вместо текущего быстрого RGB-remap.
